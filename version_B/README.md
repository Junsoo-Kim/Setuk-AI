# Setuk-AI

고등학교 교사의 세부능력 및 특기사항(세특) 작성을 돕는 로컬 VSCode 기반 AI 하네스입니다.

현재 개발 상태는 **5단계 완료: 포터블 Python 포함 배포 패키지 및 사용자 문서 구축**입니다.

## 현재 사용할 수 있는 것

- `학생정보/template.yaml`: 새 학생 파일을 만들 때 사용하는 원본 양식
- `학생정보/example.yaml`: 입력 방법을 보여 주는 가상 학생 예시
- `학생정보/README.md`: 항목별 작성 원칙과 주의사항
- `보고서/`: 학생별 DOCX 보고서를 넣는 로컬 입력 폴더 (세특·창체 공용)
- `세특/`: 이후 AI가 완성한 세특 문서를 저장할 위치
- `창체/`: 이후 AI가 완성한 창의적 체험활동(진로활동·자율활동) 문서를 저장할 위치
- `linter.py`: 세특·창체 결과물의 분량·금칙어·허용 문자를 검사하는 도구
- `rules.json`: 세특·자율활동·진로활동 공용 검사 규칙 (최대 1,500바이트). 학교와 학년도에 맞게 수정 가능
- `.agent/01_report_ingestion.md`: DOCX 보고서 1개를 읽고 학생 YAML을 생성하는 지침 (세특)
- `.agent/01c_activity_report_ingestion.md`: 순위가 매겨진 DOCX 보고서 여러 개를 읽고 학생 YAML을 생성하는 지침 (창체)
- `.agent/02_data_structuring.md`: YAML을 근거 추적이 가능한 명제로 구조화하는 지침 (세특·창체 공용)
- `.agent/03_drafting.md`: 학습 동기·탐구 활동·역량 및 성장 구조의 초안 작성 지침 (세특)
- `.agent/03c_activity_drafting.md`: 활동별로 독립된 문장 묶음을 순위 순서대로 이어 붙이는 초안 작성 지침 (창체)
- `.agent/04_evaluation.md`: 사실 보존 여부와 내용의 깊이를 평가하고 최종 파일을 저장하는 지침 (세특·창체 공용)
- `scripts/extract_docx.py`: DOCX 문단과 표를 UTF-8 JSON으로 추출하는 도구
- `scripts/run_state.py`, `scripts/review_cli.py`: 초안 완성 직후 교사 검토를 기다리는 Human-in-the-Loop 체크포인트(`run_state/`) 도구. 자세한 사용법은 `사용안내.md`의 "4-1. 초안 검토" 참고
- `run_state/`: 위 체크포인트가 진행 중인 작업 상태를 기록하는 폴더 (완료되면 자동 삭제됨)
- `AGENTS.md`: Codex와 Cline이 공통으로 사용하는 전체 실행·승인·수정 규칙
- `.clinerules/00-setuk-master.md`: Cline 전용 보완 규칙
- `.clinerules/workflows/setuk.md`: Cline에서 선택적으로 호출할 수 있는 세특 작성 워크플로
- `사용안내.md`: 설치부터 NEIS 복사까지 설명한 교사용 안내서
- `scripts/build_release.ps1`: 테스트·연기 검사 후 ZIP을 만드는 배포 스크립트

네 AI 지침은 `REPORT_INGESTED_V1 → STRUCTURED_FACTS_V1 → DRAFT_V1 → EVALUATED_RESULT_V1` 계약으로 연결됩니다. 보고서나 입력 근거가 부족하면 `REPORT_NEEDS_INPUT_V1` 또는 `NEEDS_INPUT_V1`으로 중단하여 AI가 빈 내용을 추측해 채우지 않도록 설계했습니다. `DRAFT_V1`과 `EVALUATED_RESULT_V1` 사이에는 교사가 초안을 검토·승인해야 넘어가는 Human-in-the-Loop 체크포인트가 있습니다(`run_state/`, 아래 "AI 파이프라인 실행 방법" 참고).

## AI 파이프라인 실행 방법

VSCode에서 프로젝트 폴더를 열고 Codex 또는 Cline의 새 채팅에 다음과 같이 입력합니다.

```text
김준수 세특 작업 시작해
```

이 경우 AI는 `보고서/`에서 파일명에 `김준수`가 포함된 DOCX 하나를 찾아 `학생정보/김준수.yaml`을 먼저 생성합니다. 기존 YAML이 있으면 덮어쓰기 승인을 요청합니다. 보고서 경로를 직접 지정할 수도 있습니다.

```text
보고서/김준수_물리학Ⅱ_주제탐구보고서.docx로 세특 작성해
```

이미 작성·검토한 YAML을 그대로 사용하여 보고서 입력 단계를 생략하려면 다음처럼 정확한 YAML 경로를 지정합니다.

```text
학생정보/2026-2-03-12.yaml로 세특 작성해
```

AI는 보고서 입력을 포함한 지침을 순서대로 실행합니다. 초안(`DRAFT_V1`)이 완성되면 곧바로 최종 파일을 만들지 않고 멈추며, `scripts/review_cli.py`로 교사가 검토·승인해야 이어서 평가·저장을 진행합니다(자세한 명령은 `사용안내.md`의 "4-1. 초안 검토" 참고). 저장 후에는 Linter 명령을 보여 줍니다. 사용자가 명시적으로 승인해야 검사가 실행되며, 오류 수정 후 재검사할 때도 다시 승인을 요청합니다.

### 창체(진로활동·자율활동) 실행 방법

세특과는 별도 파이프라인입니다. 세특·자율활동·진로활동 모두 최대 1,500바이트로 같은 `rules.json` 규칙을 사용합니다.

| 모드 | 트리거 예시 | 최대 분량 |
| --- | --- | --- |
| 세특 (A·B) | `<식별자> 세특 작업 시작해` | 1,500바이트 |
| 자율활동 (C) | `<식별자> 자율활동 작성해` | 1,500바이트 |
| 진로활동 (C) | `<식별자> 진로활동 작성해` | 1,500바이트 |
| 창체 분류 (D, 파일 미생성) | `<식별자> 창체 분류해줘` | 해당 없음 |
| 물리 통합 세특 (E) | `<식별자> 물리 통합 세특 작성해` | 1,500바이트 |
| 땜빵모드 (F, 공통교육 대체) | `땜빵모드 <식별자> 학생 <진로활동\|자율활동> 작성해줘, 활동 우선순위는 다음과 같아` | 1,500바이트 (하한 미적용) |

학생명, 항목(진로활동 또는 자율활동), 그리고 활동별 순위를 함께 지정합니다.

```text
신지유 진로활동 작성해. 학문 융합 프로젝트 1순위, 종합 탐구 보고서 2순위, 세기의 학자 탐구 3순위
```

AI는 `보고서/`에서 파일명에 "신지유"가 포함된 `.docx`를 모두 찾은 뒤, 순위 목록의 키워드와 파일명을 매칭합니다. 찾은 파일이 순위 목록보다 많아도 목록에 없는 파일은 사용하지 않습니다. 매칭이 애매한 항목만 확인을 요청하고, 나머지는 바로 진행합니다. 결과는 `창체/신지유_진로.md`에 활동 3개가 순위 순서대로, 각 활동이 독립된 문장 묶음으로 작성되어 저장됩니다. 활동 사이는 하나의 서사로 합쳐지지 않고 마침표 뒤 띄어쓰기 한 칸으로 구분됩니다. Linter 실행 승인을 요청하기 전에 `순위 | 사용 파일명 | 반영된 문단`을 정리한 표를 먼저 보여주므로, 승인하기 전에 출처를 확인할 수 있습니다.

순위 없이 학생명과 항목만 말하면 해당 학생명이 포함된 모든 `.docx`를 후보로 보여주고 사용할 파일과 순서를 먼저 확인합니다.

### 창체 분류 (D모드, 선택)

어떤 보고서를 진로활동에, 어떤 보고서를 자율활동에 쓸지 아직 정하지 않았다면 순위 없이 분류만 먼저 요청할 수 있습니다.

```text
강태연 창체 분류해줘
```

AI가 `보고서/`에서 학생명이 포함된 `.docx`를 모두 읽고 진로/자율 후보와 순위를 채팅으로만 보고합니다. **어떤 파일도 저장하지 않으며**, 02·03c·04 단계로 이어지지 않습니다. 실제 작성은 이 결과를 참고해 새 채팅에서 위 창체 트리거로 다시 요청해야 합니다.

### 물리학 통합 세특 (E모드)

물리학 과목 전용입니다. 자기성찰(선택)·물리신문·주제탐구 세 보고서를 하나의 세특으로 통합합니다.

```text
김준수 물리 통합 세특 작성해
```

AI는 `보고서/`에서 학생명이 포함된 `.docx`를 파일명 키워드("자기성찰"/"자기평가", "신문", "탐구")로 배타적으로 매칭합니다. 물리신문·주제탐구가 모두 없으면 다른 모드로 전환하지 않고 자료 부족을 보고합니다. 결과는 세특 모드와 동일하게 `세특/<식별자>.md`에 저장되고, 저장 전 `역할 | 사용 파일명 | 반영된 문단` 표로 출처를 확인할 수 있습니다.

### 땜빵모드 (F모드, 공통교육 대체)

학생별 실제 활동 보고서가 없어 학교 전체가 공통으로 이수한 필수교육(영어듣기평가·생명존중 및 자살예방교육·학교폭력실태조사·가정폭력예방교육·아동학대예방교육·다문화이해교육)만으로 진로활동·자율활동을 작성해야 할 때 사용합니다. `보고서/`를 전혀 읽지 않고 채팅에 직접 입력한 활동 목록만 근거로 씁니다.

```text
땜빵모드 김준수 학생 자율활동 작성해줘, 활동 우선순위는 다음과 같아
1순위: 학교폭력실태조사
2순위: 다문화이해교육
```

"땜빵모드" 시동어가 없으면 이 파이프라인은 실행되지 않고 일반 창체(C모드, 보고서 기반) 요청으로 처리됩니다. 이 모드는 `target_min_bytes`(권장 하한)를 적용하지 않습니다.

Cline에서는 자연어 요청 외에 `/setuk.md` 워크플로를 선택적으로 사용할 수 있습니다. Codex의 현재 공식 프로젝트 지침 파일은 `.codexrules`가 아니라 `AGENTS.md`이므로 이 저장소도 해당 형식을 사용합니다. Cline 역시 `AGENTS.md`를 읽으며, Cline 전용 규칙은 `.clinerules/`에 보관합니다.

## 학생정보 작성 방법

1. `학생정보/template.yaml`을 같은 폴더에 복사합니다.
2. 복사한 파일 이름을 학생을 구분할 수 있는 이름으로 바꿉니다.
3. 파일의 안내 주석을 참고하여 확인된 사실만 입력합니다.
4. 해당 사항이 없는 목록은 빈 배열(`[]`)로 유지합니다.

실제 학생의 개인정보가 Git 저장소에 올라가지 않도록 학생별 YAML 파일은 기본적으로 무시됩니다. 배포에 포함할 `template.yaml`과 가상 데이터인 `example.yaml`만 추적합니다.

## Linter 실행 방법

프로젝트 루트에서 다음 명령을 실행합니다.

```powershell
.\python_portable\python.exe linter.py "세특\학생파일.md"
```

AI가 결과를 구조적으로 읽어야 할 때는 JSON 출력을 사용할 수 있습니다.

```powershell
.\python_portable\python.exe linter.py "세특\학생파일.md" --json
```

특정 과목이나 학교 기준에 맞춰 최대 분량만 일시적으로 바꾸려면 다음과 같이 실행합니다.

```powershell
.\python_portable\python.exe linter.py "세특\학생파일.md" --max-bytes 1200
```

종료 코드는 `0`이면 통과, `1`이면 내용 규칙 위반, `2`이면 파일 또는 설정 오류를 의미합니다. 기본 목표 분량은 `rules.json`의 1,400~1,500바이트이며 ASCII 1바이트, 비ASCII 3바이트, 줄바꿈 2바이트로 계산합니다. 1,400바이트 미만은 오류가 아닌 보강 권고 경고로 표시되며, 에이전트는 입력 근거 안에서 내용을 보강합니다. 실제 허용 분량과 기재 제한은 과목·학년·학년도에 따라 달라질 수 있으므로 해당 연도의 학교생활기록부 기재요령에 맞춰 `rules.json`을 확인해야 합니다.

## 자동 테스트

외부 패키지 없이 포터블 Python으로 실행됩니다.

```powershell
.\python_portable\python.exe -m unittest discover -s tests -v
```

## 배포 ZIP 만들기

프로젝트 루트에서 다음 명령을 실행하면 전체 테스트와 배포본 연기 검사를 거쳐 `dist/Setuk-Harness-<버전>.zip`을 만듭니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_release.ps1
```

## 다른 버전

이 폴더는 B버전(무설치, VSCode + 클로드 구독)입니다. 저장소 루트 기준으로, 웹 업로드만으로 쓰는 A버전은 `version_A/` 폴더에 동결되어 있고, Claude API를 직접 호출하는 자율 멀티에이전트 C버전은 `version_C/`(별도 설치 필요)에 있습니다. 세 버전의 비교는 저장소 루트의 `기획서.md` 0장을 참고하세요.

AI 파이프라인을 실제로 실행하려면(Codex/Cline/Claude Code가 `AGENTS.md`를 인식해야 하므로) VSCode에서 저장소 루트가 아니라 **이 `version_B/` 폴더 자체**를 열어야 합니다.
