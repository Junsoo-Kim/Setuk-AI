# Setuk-Harness 교사용 사용 안내

## 1. 준비 사항

- Windows 64비트 PC
- Visual Studio Code
- Codex 또는 Cline 같은 지원 AI 확장 기능과 해당 서비스 로그인

Python은 `python_portable/`에 포함되어 있으므로 별도로 설치하거나 환경 변수를 설정할 필요가 없습니다. AI 확장 기능과 모델 사용에는 인터넷 연결 및 제공자 계정이 필요할 수 있습니다.

## 2. 처음 열기

1. 배포 ZIP을 교사만 접근할 수 있는 로컬 폴더에 압축 해제합니다.
2. VSCode에서 압축을 푼 `Setuk-Harness-<버전>` 폴더 자체를 엽니다.
3. VSCode가 작업 영역 신뢰를 묻는다면 폴더 출처를 확인한 후 승인합니다.
4. Codex 또는 Cline 확장 기능을 열고 새 채팅을 시작합니다.

공용 PC에서는 바탕 화면이나 다운로드 폴더처럼 다른 사용자가 볼 수 있는 위치를 피하고, 작업을 마친 뒤 학교의 개인정보 처리 지침에 따라 파일을 보관하거나 삭제하세요.

## 3. 보고서 또는 학생정보 입력

### 방법 A: DOCX 보고서에서 자동 생성

1. 학생 한 명의 Word 보고서를 `보고서/`에 넣습니다.
2. 파일명에 학생명을 정확히 포함합니다. 예: `이세비_물리학Ⅱ_주제탐구보고서.docx`.
3. 새 채팅에서 학생명 또는 정확한 보고서 경로를 지정합니다.

```text
보고서/이세비_물리학Ⅱ_주제탐구보고서.docx로 세특 작성해
```

AI가 보고서를 읽어 `학생정보/이세비.yaml`을 만든 뒤 나머지 세특 단계를 진행합니다. 기존 YAML이 있으면 덮어쓰기 전에 승인을 요청합니다.

배포 ZIP에는 실제 학생 DOCX가 포함되지 않습니다. 새 버전을 다른 폴더에 압축 해제했다면 기존 폴더의 보고서를 새 버전의 `보고서/`에 직접 다시 복사해야 합니다.

### 방법 B: YAML 직접 입력

1. `학생정보/template.yaml`을 같은 폴더에 복사합니다.
2. 복사본 이름을 학생 식별번호 또는 이름으로 바꿉니다. 개인정보 노출을 줄이려면 이름 대신 내부 식별번호를 권장합니다.
3. 수업에서 직접 확인한 사실만 입력합니다.
4. 해당 사항이 없는 값은 빈 문자열 또는 빈 배열로 둡니다. AI가 채우기를 기대하고 추측성 힌트를 넣지 않습니다.

예시 파일명은 `학생정보/2026-2-03-12.yaml`입니다. `template.yaml`과 `example.yaml`은 실제 학생 작업용으로 사용하지 않습니다.

## 4. 세특 작성 시작

기존 YAML을 그대로 사용하려면 새 채팅에서 정확한 파일을 지정합니다.

```text
학생정보/2026-2-03-12.yaml로 세특 작성해
```

학생명만 말하면 기존 YAML 직접 입력이 아니라 보고서 입력 모드로 시작합니다.

```text
김준수 세특 작업 시작해
```

AI는 보고서 입력, 데이터 구조화, 초안 작성을 거친 뒤 **4-1의 초안 검토 단계에서 한 번 멈춥니다.** 교사가 승인하면 평가·최종 저장으로 이어져 `세특/<학생명 또는 입력파일명>.md`에 저장됩니다. 근거가 부족하면 내용을 만들지 않고 필요한 정보를 질문합니다.

## 4-1. 초안 검토 (교사 승인 단계)

세특(A·B), 창체(C), 물리 통합 세특(E) 작업은 AI가 초안을 완성한 직후 **자동으로 최종본까지 진행하지 않고 멈춥니다.** 이 단계에서 교사가 초안을 직접 읽고, 필요하면 고친 뒤 승인해야 다음 단계(평가·최종 저장)로 넘어갑니다. (분류 전용 요청과 땜빵모드는 파일을 따로 만들지 않거나 단일 단계라 이 검토를 거치지 않습니다.)

AI가 초안 작성을 마치면 다음과 비슷한 안내와 함께 명령을 보여 줍니다.

```powershell
& '.\python_portable\python.exe' '.\scripts\review_cli.py' 'open' '<식별자>'
```

1. 이 명령을 실행하면 `run_state\<식별자>_review.md`라는 파일이 생깁니다. VSCode에서 이 파일을 엽니다.
2. 초안 그대로 괜찮으면 아무것도 고치지 않고 저장만 하거나, 표현을 다듬고 싶으면 직접 고친 뒤 저장합니다. 사실 자체(활동 내용, 수치, 결과)를 새로 만들어 넣지 않습니다 — 사실 관계를 바꾸고 싶으면 채팅으로 AI에게 근거를 다시 확인해 달라고 요청하는 편이 안전합니다.
3. 승인합니다.

```powershell
& '.\python_portable\python.exe' '.\scripts\review_cli.py' 'approve' '<식별자>'
```

4. 채팅으로 돌아가 "검토 끝났어, 계속 진행해줘"처럼 알려 주면 AI가 승인된 내용으로 평가·최종 저장 단계를 이어갑니다.

초안을 다시 쓰게 하고 싶으면 승인 대신 반려할 수 있습니다.

```powershell
& '.\python_portable\python.exe' '.\scripts\review_cli.py' 'reject' '<식별자>' '--reason' '탐구 과정을 더 구체적으로 써줘'
```

반려하면 AI가 그 사유를 반영해 초안부터 다시 작성한 뒤 같은 검토 단계로 돌아옵니다. 여러 학생을 동시에 진행 중이라 지금 누가 검토 대기 상태인지 헷갈리면 다음 명령으로 확인할 수 있습니다.

```powershell
& '.\python_portable\python.exe' '.\scripts\review_cli.py' 'status'
```

이 검토 기록(`run_state\` 폴더)은 작업이 Linter 통과까지 끝나면 자동으로 삭제되는 임시 파일이며, `세특\`이나 `창체\`의 결과물과는 별개입니다.

## 5. 창체(진로활동·자율활동) 작성 시작

세특과는 별도의 파이프라인입니다. 진로활동·자율활동 모두 최대 1,500바이트로, 세특과 같은 `rules.json` 규칙을 사용합니다.

한 학기 동안 학생이 수행한 여러 활동(보통 DOCX 2~3개)을 하나의 문서(최대 1,500바이트)로 합칠 때 사용합니다. 보고서는 세특과 마찬가지로 `보고서/`에 넣습니다.

새 채팅에서 학생명, 항목(진로활동 또는 자율활동), 활동별 순위를 함께 지정합니다.

```text
신지유 진로활동 작성해. 학문 융합 프로젝트 1순위, 종합 탐구 보고서 2순위, 세기의 학자 탐구 3순위
```

초안이 완성되면 곧바로 저장되지 않고 4-1의 초안 검토 단계를 먼저 거칩니다.

AI는 `보고서/`에서 파일명에 학생명이 포함된 DOCX를 모두 찾은 뒤, 순위 목록의 제목 키워드와 파일명을 매칭합니다. 예를 들어 학생 관련 파일이 5개 있어도 순위 목록에 있는 3개만 사용하고 나머지 2개는 사용하지 않습니다. 매칭이 애매한 항목만 확인 질문을 하고 나머지는 바로 진행합니다. 순위 없이 학생명과 항목만 말하면 찾은 파일 전체를 후보로 보여주고 사용할 파일과 순서를 먼저 확인받습니다.

결과는 `창체/<식별자>_진로.md` 또는 `창체/<식별자>_자율.md`에 저장됩니다. 활동들은 하나의 서사로 합쳐지지 않고, 각 활동이 독립된 문장 묶음으로 순위 순서대로 작성되며, 활동과 활동 사이는 마침표 뒤 띄어쓰기 한 칸으로 구분됩니다. 파일이 저장되면 AI가 Linter 실행 승인을 요청하는데, 이 승인 요청 메시지에 `순위 | 사용 파일명 | 반영된 문단`을 정리한 표가 먼저 나오므로 Linter를 승인하기 전에 어느 문단이 어느 보고서에서 나왔는지 확인할 수 있습니다.

## 5-1. 창체 활동 자동 분류 (선택)

학생 보고서가 여러 개(보통 1~4개) 있는데 어떤 보고서를 진로활동에, 어떤 보고서를 자율활동에 쓸지 아직 정하지 않았다면, 5번의 순위 지정 요청 대신 분류만 먼저 요청할 수 있습니다.

1. 학생의 Word 보고서를 전부 `보고서/`에 넣습니다. 파일명에 학생명을 정확히 포함합니다.
2. 새 채팅에서 학생명만 지정해 분류를 요청합니다.

```text
강태연 창체 분류해줘
```

3. AI가 `보고서/`에서 학생명이 포함된 `.docx`를 모두 읽고, 진로 역량이 더 뚜렷하게 드러나는 보고서일수록 진로활동 쪽으로, 나머지는 자율활동 쪽으로 나눠 순위와 함께 다음과 같이 채팅으로만 보고합니다. **어떤 파일도 새로 저장하지 않습니다.**

```text
## 진로활동 후보
1순위: ~~ 탐구
2순위: ~~ 탐구

## 자율활동 후보
1순위: 세기의 학자 탐구
2순위: ~~ 탐구
```

보고서 개수가 4개가 아니어도(1~3개) 균등하게 2:2로 나누지 않고 내용에 맞게 나눕니다. 한쪽 후보가 아예 없으면 "해당 없음"으로 보고하고, 진로/자율 판단이 애매한 보고서는 강제로 배정하지 않고 별도로 표시해 교사가 직접 확인하게 합니다.

4. 분류 결과를 확인한 뒤에는 **반드시 새 채팅**을 열어 5번의 방식대로 진로활동과 자율활동을 각각 요청합니다. 예를 들어 위 결과라면 새 채팅에서 다음과 같이 두 번 나눠 요청합니다.

```text
강태연 진로활동 작성해. ~~ 탐구 1순위, ~~ 탐구 2순위
```

```text
강태연 자율활동 작성해. 세기의 학자 탐구 1순위, ~~ 탐구 2순위
```

같은 채팅에서 분류부터 진로·자율 작성까지 이어서 요청하지 않는 것을 권장합니다. 대화가 길어질수록 이전에 읽은 보고서 내용과 지침이 계속 컨텍스트에 쌓여, 새 채팅으로 나눠 처리할 때보다 더 많은 토큰이 소비됩니다.

## 5-2. 물리학 통합 세특 작성

물리학 과목 전용 파이프라인입니다. 자기성찰(선택)·물리신문·주제탐구 세 보고서를 하나의 세특으로 통합할 때 사용합니다. 일반 세특(4번)이나 창체(5번)와는 별도이며, 이 트리거 없이는 물리학 세특 요청도 기본적으로 일반 세특 방식(보고서 1개)으로 처리됩니다.

1. 학생의 자기성찰(선택)·물리신문·주제탐구 보고서를 모두 `보고서/`에 넣습니다. 파일명에 학생명과 함께 "자기성찰"(또는 "자기평가"), "신문", "탐구" 중 해당하는 키워드를 포함합니다.
2. 새 채팅에서 다음과 같이 요청합니다.

```text
김준수 물리 통합 세특 작성해
```

AI는 파일명 키워드로 세 역할을 순서대로(자기성찰 → 물리신문 → 주제탐구) 배타적으로 매칭합니다 — 한 파일이 여러 역할에 동시에 매칭되면 먼저 매칭된 역할이 그 파일을 가져갑니다. 물리신문·주제탐구 중 매칭이 없거나 둘 이상이면 그 역할만 확인을 요청하고, 자기성찰은 없으면 조용히 생략합니다. 물리신문·주제탐구가 모두 없으면 다른 모드로 임의 전환하지 않고 자료가 부족하다고 보고합니다.

결과는 세특과 동일하게 `세특/<식별자>.md`에 저장됩니다(파일명은 물리 세특 전용 접미사를 따르지 않습니다). Linter 실행 승인을 요청하기 전에 `역할 | 사용 파일명 | 반영된 문단` 표를 먼저 보여줍니다. 자기성찰 보고서의 "수업외 질문 횟수"가 많으면(5회 이상) 그 반영 문장을 별도로 다시 보여주고 적절한지 확인을 요청합니다.

## 5-3. 땜빵모드 (공통교육 대체 창체 작성)

학생별로 실제 수행한 활동이 없어 학교 전체가 공통으로 이수한 필수교육만으로 진로활동·자율활동을 작성해야 할 때 쓰는 별도 파이프라인입니다. **`보고서/`를 전혀 읽지 않고** 채팅에 직접 입력한 활동 목록만 근거로 씁니다. 아래 6개 항목만 사용할 수 있습니다.

- 영어듣기평가
- 생명존중 및 자살예방교육
- 학교폭력실태조사
- 가정폭력예방교육
- 아동학대예방교육
- 다문화이해교육

새 채팅에서 "땜빵모드"라는 시동어와 함께 학생명, 항목(진로활동 또는 자율활동), 우선순위가 매겨진 활동 목록을 함께 지정합니다.

```text
땜빵모드 김준수 학생 자율활동 작성해줘, 활동 우선순위는 다음과 같아
1순위: 학교폭력실태조사
2순위: 다문화이해교육
```

"땜빵모드" 시동어가 없으면 이 파이프라인은 실행되지 않고 5번의 창체(보고서 기반) 요청으로 처리되니, 시동어를 빠뜨리지 않도록 주의하세요. 결과는 창체와 동일하게 `창체/<식별자>_<항목>.md`에 저장되지만, 이 모드는 분량 하한(`target_min_bytes`)을 적용하지 않으므로 항목 수가 적어 분량이 짧아도 그대로 완료됩니다.

## 6. Linter 승인과 결과 확인

최종 파일이 만들어지면 AI가 다음 형태의 명령을 보여 주고 실행 승인을 요청합니다.

```powershell
& '.\python_portable\python.exe' '.\linter.py' '.\세특\2026-2-03-12.md' '--json'
```

파일명을 확인한 뒤 승인합니다. 오류가 있으면 AI가 해당 부분만 수정하고 재실행 승인을 다시 요청합니다. 오류 0건이 되더라도 다음 사항은 교사가 직접 확인해야 합니다.

- 활동 내용이 실제 관찰 사실과 일치하는지
- 학생 간 내용이 섞이지 않았는지
- 해당 학년도·학년·과목의 학교생활기록부 기재요령을 충족하는지
- 문장의 교육적 표현과 최종 분량이 적절한지

검토가 끝나면 `.md` 파일의 본문만 NEIS에 복사합니다.

## 7. 다음 학생 작업

현재 채팅을 계속 사용하지 말고 반드시 새 채팅을 시작합니다. 이전 학생의 정보가 대화 맥락에 남아 다음 학생의 결과에 섞이는 것을 줄이기 위한 절차입니다.

## 8. 개인정보와 AI 서비스

학생 보고서, YAML과 결과 파일은 이 프로젝트 폴더의 로컬 파일로 저장되며 별도 Setuk-Harness 서버나 데이터베이스로 업로드되지 않습니다. 그러나 Codex, Cline 또는 연결한 AI 모델은 요청을 처리하기 위해 입력 내용을 외부 모델 제공자에게 전송할 수 있습니다.

사용 전 학교와 교육청의 개인정보 처리 기준, AI 서비스 계약, 데이터 보존·학습 설정을 확인하세요. 허용되지 않는 경우 실제 이름 대신 식별번호를 사용하거나 승인된 모델 환경을 사용해야 합니다. 이 도구는 개인정보 보호 준수를 자동으로 보증하지 않습니다.

## 9. 문제 해결

- **AI가 지침을 따르지 않음:** 프로젝트의 최상위 폴더를 열었는지 확인하고 새 채팅을 시작합니다. Cline에서는 Rules 패널에서 프로젝트 규칙이 활성화되어 있는지 확인합니다.
- **포터블 Python 누락 오류:** `python_portable/python.exe`가 존재하는지 확인하고 ZIP을 다시 압축 해제합니다.
- **Windows 보안 경고:** 파일 출처를 확인합니다. 학교 보안 담당자의 승인 없이 보안 기능을 우회하지 마세요.
- **Linter 종료 코드 1:** 본문 규칙 위반입니다. 표시된 진단을 수정한 뒤 다시 검사합니다.
- **Linter 종료 코드 2:** 파일 또는 `rules.json` 설정 오류입니다. 본문을 임의로 고치지 말고 설정과 경로를 확인합니다.
- **금칙어 오탐:** 교사가 해당 연도 기재요령을 확인한 뒤 `rules.json`을 관리 책임자와 함께 조정합니다.

## 10. 책임 범위

Linter는 바이트 수, 설정된 금칙어, 허용 문자만 기계적으로 검사합니다. 기본 목표 분량은 세특·자율활동·진로활동 모두 1,400~1,500바이트이며, 목표 하한 미만이면 입력 근거 안에서 보강하되 없는 사실을 만들어 분량을 채우지는 않습니다. 실제 허용 분량은 학년도별 학교생활기록부 기재요령에 따라 달라질 수 있으므로 매 학년도 초 확인이 필요합니다. AI 결과의 사실성, 교육적 타당성, 최신 규정 준수와 NEIS 최종 입력 책임은 교사에게 있습니다.
