# 01c. 창체(진로활동·자율활동) 다중 보고서 입력 및 YAML 생성

## 역할

`보고서/`에 있는 지정 학생의 Word 보고서 여러 개(사용자가 지정한 순위 목록에 대응)를 읽고, 창체(진로활동 또는 자율활동) 작성에 필요한 사실만 `학생정보/<학생명>_<항목>.yaml`에 활동 목록으로 정리하여 저장한다. `01_report_ingestion.md`와 사실 추출 원칙은 동일하지만, 입력이 보고서 하나가 아니라 순위가 매겨진 여러 개라는 점이 다르다.

## 입력

- 사용자가 지정한 학생명
- 사용자가 지정한 항목: `진로활동` 또는 `자율활동`
- 사용자가 제공한 순위 목록(활동 제목 키워드와 순위 번호의 짝). 순위 목록이 없으면 학생명이 포함된 모든 `.docx`를 후보로 다룬다.
- `학생정보/template.yaml`
- `보고서/` 아래의 해당 학생 `.docx` 파일 여러 개

## 보고서 파일 결정

`AGENTS.md`의 "C. 순위 기반 다중 보고서 입력 모드" 규칙을 그대로 따른다. 요약하면 다음과 같다.

1. `보고서/`에서 파일명에 학생명이 포함된 `.docx`를 전부 나열한다. 문서 내용을 열어 학생을 탐색하지 않는다. `~$`로 시작하는 Word 임시 파일은 제외한다.
2. 순위 목록이 있으면 각 항목의 키워드가 파일명에 포함된 파일을 하나씩 매칭한다. 목록에 없는 나머지 파일은 사용하지 않는다.
3. 매칭이 정확히 하나인 항목은 바로 사용한다. 매칭이 없거나 둘 이상인 항목만 사용자에게 확인한다.
4. 순위 목록이 없으면 나열된 후보 전체를 사용자에게 보여주고 사용할 파일과 순서를 확인받는다.
5. 정규화한 경로가 `보고서/` 밖을 가리키거나 확장자가 `.docx`가 아니면 거부한다.
6. 확정된 파일과 순위의 대응 관계를 `priority_map`으로 기록해 이후 단계와 완료 보고에서 그대로 사용한다.

## DOCX 텍스트 추출

확정된 파일마다 다음 형식으로 포터블 추출기를 실행하여 문단과 표 텍스트를 UTF-8 JSON으로 받는다. 한 번의 명령에는 파일 하나만 인자로 전달하며, 확정된 파일 수만큼 반복 실행한다.

```powershell
& '.\python_portable\python.exe' '.\scripts\extract_docx.py' '.\보고서\<보고서파일>.docx' '--json'
```

- 종료 코드가 0이 아니거나 JSON을 읽을 수 없는 파일이 있으면 해당 파일만 실패로 기록하고, 나머지 확정 파일 처리를 계속할지 사용자에게 확인한다.
- `media_files`가 비어 있지 않고 본문이 이미지·그래프를 참조하면 이미지에서 결과를 추측하지 말고, 핵심 정보가 이미지에만 있는지 사용자에게 확인한다.
- 인터넷 검색이나 외부 자료로 보고서 내용을 보충하거나 사실을 교정하지 않는다.

## 손상되거나 이해할 수 없는 보고서 처리

각 파일마다 `01_report_ingestion.md`의 "손상되거나 이해할 수 없는 보고서 처리" 기준(추출 오류, 극히 적은 문단, 빈 견본 양식, 판단 불가능한 내용, 요청 주제와 무관해 보임)을 그대로 적용한다. 다중 입력이므로 다음을 추가로 지킨다.

- 문제가 확인 파일 중 일부에서만 발생하면 임의로 그 파일을 제외하고 진행하지 않는다. 어떤 파일에서 무엇이 문제인지 구체적으로 설명하고, (a) 문제 파일을 제외하고 나머지로 계속할지 (b) 전체 작업을 중단하고 파일을 다시 확인할지 사용자에게 선택하게 한다.
- 순위 목록에서 특정 순위에 매칭된 파일이 손상·이해 불가로 판정되면, 그 순위의 활동을 통째로 빠뜨릴 수 있다는 점을 질문에 명시한다. 다른 순위의 정상 파일로 임의로 대체하지 않는다.
- 문제 파일을 제외하기로 확정되기 전까지는 그 파일의 내용을 YAML에 반영하지 않는다.

## 학생 신원 확인

파일마다 다음을 확인한다.

1. 본문에서 명시된 학생명과 학번을 찾는다.
2. 본문 학생명이 사용자가 지정한 학생명과 다르면 해당 파일만이 아니라 작업 전체를 즉시 중단한다.
3. 확정된 파일들 사이에서 학번 표기가 실질적으로 다르면(같은 해석 규칙 적용 불가) 임의로 하나를 선택하지 않고 충돌을 보고한다. `3-5-21`, `3521`, `30521`처럼 구분자나 반의 앞자리 0만 다른 표기는 같은 학번으로 해석할 수 있으며, 해석 근거를 YAML 주석에 남긴다.
4. 학기·담당 교사는 보고서에 명시되어 있을 때만 입력한다.

## 추출 원칙과 사실·평가의 경계

파일마다 `01_report_ingestion.md`의 "추출 원칙"과 "사실과 평가의 경계"를 그대로 적용해 활동 단위(`topic`, `motivation`, `process`, `evidence`, `result`, `competencies`, `growth`, `teacher_observation`)를 추출한다. 보고서에 없는 실험·독서·질문·수치·결과·감정·역할을 추가하지 않고, 조사로 얻은 설명과 직접 확인한 결과를 구분하며, 실패한 결과를 성공으로 바꾸지 않는다.

## 불일치 처리

파일별 불일치 처리는 `01_report_ingestion.md`의 "비차단 불일치"·"차단 불일치" 기준을 그대로 따른다. 다음은 창체 다중 입력에서 추가로 적용한다.

- 한 파일에서 발생한 비차단 불일치는 해당 파일의 활동에만 적용하고 다른 활동에 영향을 주지 않는다.
- 어느 한 파일이 차단 불일치로 중단 조건에 해당하면 그 파일의 활동만 제외하고 나머지 확정 파일로 계속할지, 전체를 중단할지 사용자에게 확인한다. 임의로 결정하지 않는다.

## 활동 순서와 메타데이터

- YAML의 `activities` 목록 순서는 사용자가 지정한 순위(1→2→3)를 그대로 따른다.
- 활동마다 `priority`(순위 번호)와 `source_report`(사용한 `.docx`의 `보고서/` 기준 상대 경로)를 기록한다. 이 두 값은 이후 03c·완료 보고 단계에서 활동과 보고서를 연결하는 유일한 근거이므로 임의로 바꾸지 않는다.

## 요구사항 생성

- `requirements.emphasis`에는 근거가 구체적이고 탐구·활동 역량을 평가하기 좋은 행동을 활동별로 기록한다.
- `requirements.exclude`에는 실패를 성공으로 오해할 가능성, 조사와 실험의 혼동, 보고서에 없는 교사 관찰 등 반드시 피해야 할 표현을 기록한다.
- `target_bytes`는 사용자가 별도 분량을 요구하지 않으면 `null`로 둔다. 활동별 바이트 배분은 03c 단계의 책임이다.

## 저장 경로와 덮어쓰기

1. 출력 파일명은 `학생정보/<학생명>_<항목>.yaml`로 한다. `<항목>`은 `진로` 또는 `자율`이다.
2. 학생명에서 Windows 파일명에 사용할 수 없는 문자를 제거한다. 제거 후 이름이 비거나 경로가 `학생정보/` 밖으로 벗어나면 저장하지 않는다.
3. 출력 YAML이 이미 있으면 기존 파일의 크기와 경로만 확인하고, 내용을 읽거나 덮어쓰기 전에 사용자에게 명시적으로 승인받는다.
4. 승인받지 않은 기존 YAML을 변경하지 않는다.
5. UTF-8로 저장하며 아래 출력 YAML 형식과 동일한 키 구조를 사용한다.
6. 파일 첫 주석에 사용한 모든 보고서의 상대 경로를 순위와 함께 기록한다.

## 출력 YAML 형식

모든 문자열은 YAML 문법이 깨지지 않도록 큰따옴표로 감싼다. 해당 내용이 없으면 빈 문자열 또는 빈 배열로 둔다.

```yaml
# 출처(순위순): 1순위 보고서/<파일A>.docx, 2순위 보고서/<파일B>.docx, 3순위 보고서/<파일C>.docx
schema_version: 1

student:
  name: ""
  grade: ""
  class: ""
  number: ""

category: ""  # "진로활동" 또는 "자율활동"

activities:
  - priority: 1
    source_report: "보고서/<파일A>.docx"
    topic: ""
    motivation: ""
    process: []
    evidence: []
    result: ""
    competencies: []
    growth: ""
    teacher_observation: ""

overall_observation: ""

requirements:
  target_bytes: null
  emphasis: []
  exclude: []
```

## 중단 조건

다음 중 하나라도 해당하면 YAML을 만들지 않고 `REPORT_NEEDS_INPUT_V1`을 반환한다.

- 학생명 또는 항목(진로활동/자율활동)이 불명확함
- 순위 목록의 항목에 매칭되는 보고서 후보가 없거나 둘 이상인데 사용자 확인을 받지 못함
- 확정된 모든 파일에서 본문을 추출할 수 없음
- 확정된 파일들 사이에서 학생 신원이 서로 달라 하나로 확정할 수 없음
- 모든 활동에서 과정과 결과에 해당하는 실질적인 내용이 없음

```yaml
contract: REPORT_NEEDS_INPUT_V1
report_path: ""
active_report_directory: "보고서/"
available_docx_filenames: []
questions:
  - field: ""
    question: ""
```

## 완료 보고 계약: `REPORT_INGESTED_V1`

```yaml
contract: REPORT_INGESTED_V1
report_paths: ["보고서/<파일A>.docx", "보고서/<파일B>.docx", "보고서/<파일C>.docx"]
student_name: ""
category: "진로활동"
yaml_path: "학생정보/<학생명>_<항목>.yaml"
saved: true
activity_count: 3
priority_map:
  - priority: 1
    source_report: "보고서/<파일A>.docx"
    activity_id: A1
uncertain_fields: []
warnings: []
excluded_uncertain_facts: []
```

모든 계약 응답은 `yaml` 코드 블록 하나로 끝까지 출력한다. 실제 파일명은 `*` 같은 Markdown 문자로 바꾸지 말고 파일 시스템에서 확인한 문자열을 그대로 복사한다. 완료 후에는 YAML 경로, 활동 수, 순위-파일 대응, 비워 둔 불확실 필드와 비차단 경고만 보고한다. 보고서 전문이나 학생 개인정보를 채팅에 반복 출력하지 않는다.
