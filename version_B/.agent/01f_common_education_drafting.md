# 01f. 공통교육 대체 창체 작성 (땜빵모드)

## 역할

실제 개별 활동이 없어 학교 전체가 공통으로 이수한 필수교육만으로 진로활동 또는 자율활동 특기사항을 작성한다. 학생별 보고서(`.docx`)를 읽지 않으며, 사용자가 채팅에서 직접 지정한 활동 목록만 근거로 사용한다. `02_data_structuring.md`·`03c_activity_drafting.md`·`04_evaluation.md`는 이 모드에서 사용하지 않는다 — 이 파일 하나로 입력부터 저장까지 끝낸다.

## 입력

- 사용자가 지정한 학생명
- 사용자가 지정한 항목: `진로활동` 또는 `자율활동`
- 사용자가 우선순위와 함께 지정한 활동 목록. 각 항목명은 아래 "공통교육 목록"의 항목명과 명백히 대응해야 한다.
- (진로활동에서만, 선택) 사용자가 지정한 희망분야

## 공통교육 목록과 기본 내용

아래 6개 항목만 이 모드에서 사용할 수 있다. 지정된 활동명이 이 목록 중 어느 것과도 명백히 대응하지 않으면 임의로 항목을 만들지 않고 사용자에게 정확한 항목명을 확인한다.

| 항목 ID | 항목명 | 기본 내용(모든 학생 공통, 사실로 사용 가능) |
|---|---|---|
| A | 영어듣기평가 | 학사 일정에 따라 실시된 영어듣기평가에 응시함 |
| B | 생명존중 및 자살예방교육 | 생명 존중과 자살 예방을 주제로 한 교육에 참여하여 생명의 소중함과 위기 상황에서의 도움 요청 방법을 학습함 |
| C | 학교폭력실태조사 | 학교폭력 실태조사에 성실히 참여함 |
| D | 가정폭력예방교육 | 가정폭력 예방교육 영상을 시청하고 가정 내 폭력의 심각성과 대처 방법을 학습함 |
| E | 아동학대예방교육 | 아동학대 예방교육에 참여하여 아동학대의 유형과 신고 의무를 학습함 |
| F | 다문화이해교육 | 다문화 이해교육에 참여하여 문화적 다양성을 존중하는 태도를 기름 |

"기본 내용"은 특정 학생의 개별 행동이 아니라 해당 교육이 공통으로 다루는 내용이므로 모든 학생에게 동일하게 사실로 사용할 수 있다. 표에 없는 세부 사실(수치, 개인 반응, 소감, 날짜, 교시)을 새로 만들지 않는다.

## 절대 금지

- 이 학생만 관찰했다는 근거가 없는 상태에서 `~역량이 드러남`, `~을 보여줌`처럼 개별 역량을 평가하는 문장을 쓰지 않는다. 이 모드는 참여 사실과 그 교육이 다루는 일반적 인식·태도까지만 서술하고, 그 이상의 개인별 평가는 만들지 않는다. (`03c_activity_drafting.md`의 "활동별 최대 1개 교사 평가" 요구는 이 모드에 적용하지 않는다.)
- 활동 사이에 `이어서`, `이를 바탕으로`, `이러한 경험을 토대로` 같은 서사적 접속 표현을 쓰지 않는다. 각 항목은 독립된 문장(묶음)으로 작성한다.
- 날짜, 교시, 학생 이름, 학년, 반, 번호를 본문에 넣지 않는다.
- "공통교육 목록"에 없는 활동을 임의로 추가하지 않는다.
- 같은 학생의 진로활동과 자율활동 양쪽에 동일한 항목 ID를 함께 쓰지 않는다. 사용자가 두 요청(같은 학생, 각각 다른 항목)에서 동일 항목을 중복 지정하면 그대로 진행하지 말고 확인을 요청한다 — 단, 이 모드는 매 요청이 새 채팅일 수 있어 이전 요청 내역을 알 수 없으므로, 같은 요청 안에서 중복이 있을 때만 확인하면 된다.

## 문장 작성 규칙

- 각 항목은 `<항목명>에 참여하여/시청하고/응시하여 <기본 내용>.` 형태로 항목명을 문장 앞에 자연스럽게 포함해 시작한다. 표의 "기본 내용" 문구를 그대로 복사하지 말고 자연스러운 종결어미로 다듬는다.
- 항목 순서는 사용자가 지정한 우선순위(1→2→3…)를 그대로 따른다.
- 항목과 항목 사이는 마침표 뒤 띄어쓰기 한 칸으로만 구분한다. 줄바꿈, 빈 줄, 글머리 기호, 번호, Markdown 문법을 쓰지 않는다.
- **자율활동**: 참여 사실과 그 교육이 다루는 인식·태도까지만 쓴다. 예: `학교폭력 실태조사에 성실히 참여함.`
- **진로활동**: 같은 참여 사실 뒤에 자기관리·사회적 책임·진로 탐색과 자연스럽게 이어지는 짧은 절을 덧붙인다. 희망분야가 주어졌으면 그 표현을 활용해 `○○ 분야를 희망하는 가운데 ~을 인식함`처럼 이미 일어난 사실(생각의 확인)로만 연결하고, 그 진로의 성공 가능성이나 적합성을 예측하지 않는다. 희망분야가 없으면 특정 진로를 지어내지 말고 일반적인 자기관리·사회 구성원으로서의 태도로 연결한다.
- `매우`, `탁월한`, `훌륭한`, `남다른` 같은 근거 없는 강조를 쓰지 않는다.
- Markdown 제목, 목록, 굵게 표시, 코드 표시를 쓰지 않는다.

## 분량 규칙

- `rules.json`의 `max_bytes`(1,500바이트)만 상한으로 지킨다. `target_min_bytes`(권장 하한)는 이 모드에 적용하지 않는다 — 분량을 채우기 위해 항목을 반복하거나 근거 없는 문장을 추가하지 않는다.
- Linter 결과에 `BELOW_TARGET_LENGTH` 경고가 있어도 오류가 0건이면 그대로 완료 처리한다. `AGENTS.md` 5번 "목표 분량 보강" 절차는 이 모드에서 실행하지 않는다.
- 사용자가 지정한 항목 수가 적어 분량이 짧더라도 그대로 완료한다.

## 저장

1. 사용한 항목을 우선순위와 함께 `학생정보/<학생명>_<항목>.yaml`에 저장한다(아래 형식). 이미 있으면 기존 파일의 크기와 경로만 확인하고 덮어쓰기 승인을 받는다.
2. 최종 본문을 `창체/<학생명>_<항목>.md`에 저장한다. 이미 있으면 덮어쓰기 승인을 받는다.
3. UTF-8로 저장하며 파일 본문은 줄바꿈 없는 한 문단의 일반 텍스트다.

### 학생정보 YAML 형식

```yaml
# 땜빵모드(공통교육 대체 입력) — 원본 보고서 없음
schema_version: 1
student:
  name: ""
category: ""  # "진로활동" 또는 "자율활동"
desired_field: ""  # 진로활동에서 사용자가 제공한 경우에만. 없으면 빈 문자열.
activities:
  - priority: 1
    topic_id: ""
    topic: ""
```

## 승인 게이트에 제시할 표

`AGENTS.md` 4번(실행 승인 게이트)의 창체 모드 표와 동일한 취지로, Linter 실행 승인을 요청하기 전에 다음 표를 먼저 보여준다. 열은 `우선순위 | 항목명 | 반영된 문장`이며, 최종 저장된 본문을 마침표 뒤 띄어쓰기로 나눈 문장 묶음을 우선순위 순서대로 그대로 인용한다.

## 완료 보고

다른 모드와 동일하게 저장 경로·바이트 수·Linter 오류 0건을 보고하되, 목표 하한 충족 여부는 보고하지 않는다(이 모드는 하한을 적용하지 않는다는 점을 대신 한 줄로 명시한다).

## 중단 조건

다음 중 하나라도 해당하면 저장하지 않고 질문만 반환한다.

- 학생명 또는 항목(진로활동/자율활동)이 불명확함
- 지정된 활동명이 "공통교육 목록" 6개 항목 중 어느 것과도 명백히 대응하지 않음
- 같은 요청 안에서 진로활동과 자율활동에 동일 항목이 중복 지정됨

```yaml
contract: REPORT_NEEDS_INPUT_V1
questions:
  - field: ""
    question: ""
```
