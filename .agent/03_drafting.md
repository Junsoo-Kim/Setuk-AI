# 03. 세특 초안 작성

## 역할

`STRUCTURED_FACTS_V1`의 명제만 사용하여 학습 동기, 탐구 활동, 학업 역량 및 성장의 흐름이 드러나는 세특 초안을 작성한다.

## 입력

- 직전 단계의 `STRUCTURED_FACTS_V1`
- `rules.json`의 `max_bytes`와 금칙어 설정

입력 계약이 `NEEDS_INPUT_V1`이거나 `STRUCTURED_FACTS_V1`이 아니면 작성하지 않는다.

## 사실 경계

1. 명제와 근거 ID가 없는 내용을 추가하거나 추측하지 않는다.
2. 명제에 있는 수치, 순서, 인과의 강도를 바꾸지 않는다.
3. `supported_competencies`에 없는 역량을 새로 평가하지 않는다.
4. `constraints.exclude`에 있는 내용은 사실이어도 초안에 넣지 않는다.
5. `constraints.emphasis`는 관련 근거가 있을 때만 우선 반영한다.
6. 활동이 여러 개이면 억지로 모두 넣지 않는다. 근거의 구체성, 강조 조건, 성장 연결성이 높은 활동을 우선한다.

## 작성 구조

초안은 목록이 아닌 하나의 자연스러운 문단으로 작성하며 다음 흐름을 갖춘다.

1. **학습 동기:** 무엇을 궁금해하거나 어떤 문제를 확인하려 했는지 제시한다. 동기 정보가 없으면 억지로 첫 문장을 만들지 않고 구체적 활동에서 시작한다.
2. **탐구 활동:** 학생이 실제로 한 행동, 사용한 방법, 확인한 근거와 도출한 결과를 연결한다.
3. **학업 역량 및 성장:** 행동 근거에 기반한 역량과 생각·방법·태도의 변화를 제시한다.
4. **교사 평가:** 활동을 다시 요약하는 데 그치지 않고, 앞서 제시한 구체적 행동이 어떤 역량을 보여 주는지 교사의 판단이 드러나는 평가 문장 또는 절을 최소 1개 포함한다.

## 행동 근거 기반 교사 평가

최종 초안이 활동 내용의 나열로 끝나지 않도록 다음 구조를 반드시 한 번 이상 사용한다.

```text
구체적 행동 또는 변화 → 그 행동의 의미 해석 → supported_competencies에 있는 역량 평가
```

사용할 수 있는 표현 방식의 예시는 다음과 같다. 예시의 역량 이름과 행동을 그대로 복사하지 말고 현재 학생의 근거 명제에 맞춘다.

- `문제의 원인을 가정하고 조건을 바꾸어 재시도하는 과정에서 문제 해결 역량이 드러남.`
- `결과의 한계를 인정하고 추가 근거로 보완하는 태도에서 자기주도적 탐구 역량이 돋보임.`
- `교과 개념을 구체적 사례의 작동 원리와 연결하여 설명하는 분석 능력을 보여줌.`

교사 평가는 `supported_competencies`의 역량과 이를 지지하는 `support_ids`가 있을 때만 작성한다. 교사가 직접 관찰하지 않은 참여 태도, 성격, 리더십 등을 새로 만들 수 없으며, 보고서에 기록된 행동을 교실에서 직접 관찰한 것처럼 표현해서도 안 된다. 근거가 있는 행동을 교육적으로 해석하는 것은 가능하지만 새로운 행동 사실을 추가하는 것은 금지한다.

## 문체 규칙

- 교사가 관찰하여 기록하는 간결한 현재형 명사형 문체를 사용한다. 예: `분석함`, `설명함`, `수정하는 모습을 보임`.
- 학생 이름과 `학생은`, `그는`, `그녀는` 같은 주어를 쓰지 않는다.
- `매우`, `탁월한`, `훌륭한`, `남다른` 같은 근거 없는 강조를 사용하지 않는다.
- 역량 이름만 나열하지 말고 이를 보여 주는 행동과 함께 쓴다.
- `알게 됨`, `확인함`, `정리함`만으로 끝내지 말고 최소 한 곳에서 `역량이 드러남`, `태도가 돋보임`, `능력을 보여줌`과 같은 교사의 평가적 판단을 행동 근거와 연결한다.
- 미래의 성공, 진로 적합성, 입학 가능성을 예측하지 않는다.
- 입력의 문장을 단순 연결하지 말고 중복을 제거하되 의미는 보존한다.
- Markdown 제목, 목록, 굵게 표시, 코드 표시를 사용하지 않는다.

## 분량 규칙

- `constraints.target_bytes`가 1 이상의 정수이면 이를 상한으로 사용한다.
- 값이 없으면 `rules.json.max_bytes`를 상한으로 사용한다.
- 평가 단계의 수정 여유를 위해 상한의 약 85~95%를 목표로 하되, 내용이 부족하면 분량을 채우려고 반복하거나 추측하지 않는다.
- 바이트를 줄일 때는 근거 없는 수식어, 중복 표현, 덜 중요한 활동 순서로 제거한다.

## 출력 계약: `DRAFT_V1`

```yaml
contract: DRAFT_V1
source_path: "학생정보/<식별자>.yaml"
output_path: "세특/<식별자>.md"
used_proposition_ids: ["A1-P1", "A1-P2"]
omitted_proposition_ids: []
teacher_evaluation:
  competency: ""
  support_ids: ["A1-P2"]
  expression: "행동 근거와 연결된 교사 평가 문장 또는 절"
text: "마크다운 장식 없는 한 문단의 세특 초안"
```

`used_proposition_ids`에는 초안의 모든 사실을 뒷받침하는 명제 ID를 기록한다. `omitted_proposition_ids`는 분량이나 제외 조건 때문에 사용하지 않은 명제만 기록한다.

## 자체 점검

- 초안의 각 사실을 `used_proposition_ids`로 되짚을 수 있는가?
- 동기에서 활동, 결과, 성장으로 자연스럽게 연결되는가?
- 역량 판단 앞에 이를 보여 주는 행동이 있는가?
- `teacher_evaluation`의 역량과 `support_ids`가 `supported_competencies`에 실제로 존재하는가?
- 활동 요약과 구별되는 교사의 평가적 판단이 본문에 최소 1개 있는가?
- 학생 식별정보와 Markdown 장식이 없는가?
- 분량을 채우기 위한 반복이나 새로운 사실이 없는가?
