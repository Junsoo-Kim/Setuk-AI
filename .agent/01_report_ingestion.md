# 01. 학생 보고서 입력 및 YAML 생성

## 역할

`보고서/`에 있는 지정 학생의 Word 보고서 하나를 읽고, 이후 세특 작성에 필요한 사실만 `학생정보/<학생명>.yaml`에 정리하여 저장한다. 보고서의 내용을 요약하는 단계가 아니라, 세특 생성에 사용할 수 있는 근거와 한계를 템플릿 구조로 변환하는 단계이다.

## 입력

- 사용자가 지정한 학생명 또는 정확한 DOCX 경로
- `학생정보/template.yaml`
- `보고서/` 아래의 해당 학생 `.docx` 파일 하나

## 보고서 파일 결정

1. 사용자가 정확한 `보고서/<파일명>.docx` 경로를 지정하면 그 파일만 사용한다.
2. 학생명만 지정한 경우 파일명에 해당 학생명이 정확히 포함된 `.docx`를 파일명만으로 찾는다. 문서 내용을 열어 학생을 탐색하지 않는다.
3. `~$`로 시작하는 Word 임시 파일은 제외한다.
4. 후보가 없으면 현재 작업공간의 `보고서/` 절대 경로와 발견된 DOCX 파일명만 보고하고, 해당 작업공간에 파일을 복사하거나 정확한 경로를 지정해 달라고 요청한다. 다른 위치를 추측하여 검색하지 않는다.
5. 후보가 둘 이상이면 문서를 열지 말고 후보 파일명을 코드 표시로 정확히 나열한 뒤 하나를 지정해 달라고 요청한다.
6. 정규화한 경로가 `보고서/` 밖을 가리키거나 확장자가 `.docx`가 아니면 거부한다.
7. 한 작업에서는 선택한 DOCX 하나만 읽고 다른 학생 보고서를 함께 열지 않는다.

## DOCX 텍스트 추출

Word 바이너리를 임의의 인코딩으로 직접 읽지 않는다. 다음 형식으로 포터블 추출기를 실행하여 문단과 표 텍스트를 UTF-8 JSON으로 받는다.

```powershell
& '.\python_portable\python.exe' '.\scripts\extract_docx.py' '.\보고서\<보고서파일>.docx' '--json'
```

- 추출 명령에는 확정된 보고서 경로 하나만 별도 인자로 전달한다.
- 종료 코드가 0이 아니거나 JSON을 읽을 수 없으면 YAML을 만들지 않고 오류를 보고한다.
- `media_files`가 비어 있지 않고 본문이 이미지·그래프를 참조하면 이미지에서 결과를 추측하지 말고, 핵심 정보가 이미지에만 있는지 사용자에게 확인한다.
- 인터넷 검색이나 외부 자료로 보고서 내용을 보충하거나 사실을 교정하지 않는다. 보고서가 주장한 내용은 보고서의 주장으로만 정리한다.

## 학생 신원 확인

1. 본문에서 명시된 학생명과 학번을 찾는다.
2. 본문 학생명이 사용자가 지정한 학생명과 다르면 즉시 중단한다.
3. 파일명과 본문의 학번 표기가 실질적으로 다르면 임의로 하나를 선택하지 않고 충돌을 보고한다. `3-5-21`, `3521`, `30521`처럼 구분자나 반의 앞자리 0만 다른 표기는 같은 학번으로 해석할 수 있지만 YAML 주석에 해석 근거를 남긴다.
4. 학년·반·번호로 명확히 분리할 수 없는 학번은 원문을 임의 분해하지 말고 사용자에게 확인한다.
5. 학기와 담당 교사는 보고서에 명시되어 있을 때만 입력한다. 제출일만으로 학기를 추론하지 않는다.

## 추출 원칙

보고서에서 다음 정보를 활동 단위로 추출한다.

- `topic`: 탐구 제목과 실제 범위
- `motivation`: 학생이 밝힌 질문, 문제의식, 진로·교과 연결 동기
- `process`: 조사, 실험, 비교, 분석, 발표, 수정 등 실제 수행 행동
- `evidence`: 측정값, 관찰 결과, 산출물, 실패 결과, 인용 자료를 통해 확인한 내용
- `result`: 학생이 도출하거나 정리한 결론
- `competencies`: 행동 근거로 평가 가능한 역량 후보
- `growth`: 학생이 보고서에서 밝힌 이해·방법·태도의 변화
- `teacher_observation`: 교사의 직접 관찰 또는 첨삭이 문서에 명시된 경우에만 입력
- `overall_observation`: 교사의 종합 평가가 문서에 명시된 경우에만 입력

## 사실과 평가의 경계

1. 보고서에 없는 실험, 독서, 질문, 수치, 결과, 감정, 역할을 추가하지 않는다.
2. 조사로 얻은 설명과 학생이 실험으로 직접 확인한 결과를 구분한다.
3. 실패하거나 결과를 얻지 못한 실험을 성공한 것으로 바꾸지 않는다.
4. 학생의 자기서술을 교사의 직접 관찰로 바꾸지 않는다.
5. `competencies`에는 보고서의 구체적 행동으로 뒷받침되는 평가 후보만 넣는다. 성격, 리더십, 참여도는 명시적 근거가 없으면 넣지 않는다.
6. 출처 URL이나 참고문헌 제목은 탐구 과정을 이해하는 데 꼭 필요한 경우가 아니면 세특 입력 데이터에 그대로 복사하지 않는다.
7. 향후 계획은 실제 수행 결과와 분리한다. 아직 하지 않은 활동을 `process`나 `evidence`에 넣지 않는다.

## 불일치 처리

보고서의 모든 오기와 불일치가 전체 파이프라인의 중단 사유는 아니다.

### 비차단 불일치

단위 오기, 한 수치의 오탈자, 문장 일부의 국소적 모순처럼 해당 사실만 제외해도 학생 신원·탐구 주제·주요 과정·결론을 안전하게 정리할 수 있으면 계속 진행한다.

1. 잘못된 것으로 보이는 값을 자동으로 고쳐 쓰지 않는다.
2. 충돌한 원문 수치는 YAML의 `evidence`와 `result`에서 제외한다.
3. 나머지 문장으로 확인되는 안정적인 사실만 기록한다.
4. `requirements.exclude`에 해당 수치를 확정 사실처럼 쓰지 말라는 조건을 추가한다.
5. `REPORT_INGESTED_V1.warnings`와 `excluded_uncertain_facts`에 원문 불일치와 처리 방법을 기록한다.

예를 들어 실험 조건과 역산 결과는 일관되지만 무늬 길이의 단위만 맞지 않으면, 단위를 임의로 교정하거나 전체 작업을 멈추지 않는다. 해당 무늬 길이는 제외하고 `보고서에는 단위 불일치가 있어 원문 수치를 사용하지 않음`이라고 경고한다.

### 차단 불일치

다음은 `REPORT_NEEDS_INPUT_V1`으로 중단한다.

- 요청 학생명과 본문 학생명이 다름
- 서로 다른 학번으로 해석되어 학생 신원을 확정할 수 없음
- 어느 활동이 실제 수행되었는지 판단할 수 없음
- 핵심 실험의 성공·실패 또는 결론이 서로 반대이며 충돌 부분을 제외하면 활동을 정리할 수 없음
- 필수 내용이 이미지에만 있어 텍스트로 확인할 수 없음

## 요구사항 생성

- `requirements.emphasis`에는 근거가 구체적이고 학생의 탐구 역량을 평가하기 좋은 행동을 기록한다.
- `requirements.exclude`에는 실패한 활동을 성공으로 오해할 가능성, 조사와 실험의 혼동, 보고서에 없는 교사 관찰 등 반드시 피해야 할 표현을 기록한다.
- `target_bytes`는 보고서가 별도 분량을 요구하지 않으면 `null`로 둔다.

## 저장 경로와 덮어쓰기

1. 출력 파일명은 본문에서 확인한 학생명을 사용한 `학생정보/<학생명>.yaml`로 한다.
2. 학생명에서 Windows 파일명에 사용할 수 없는 문자를 제거한다. 제거 후 이름이 비거나 경로가 `학생정보/` 밖으로 벗어나면 저장하지 않는다.
3. 출력 YAML이 이미 있으면 기존 파일의 크기와 경로만 확인하고, 내용을 읽거나 덮어쓰기 전에 사용자에게 명시적으로 승인받는다.
4. 승인받지 않은 기존 YAML을 변경하지 않는다.
5. UTF-8로 저장하며 `template.yaml`의 `schema_version: 1`과 동일한 키 구조를 사용한다.
6. 파일 첫 주석에 원본 보고서의 상대 경로를 기록한다.

## 출력 YAML 형식

모든 문자열은 YAML 문법이 깨지지 않도록 큰따옴표로 감싼다. 해당 내용이 없으면 빈 문자열 또는 빈 배열로 둔다.

```yaml
# 출처: 보고서/<파일명>.docx
schema_version: 1

student:
  name: ""
  grade: ""
  class: ""
  number: ""

subject:
  name: ""
  semester: ""
  teacher: ""

activities:
  - topic: ""
    motivation: ""
    process: []
    evidence: []
    result: ""
    competencies: []
    growth: ""
    teacher_observation: ""

overall_observation: ""

requirements:
  target_bytes: null
  emphasis: []
  exclude: []
```

## 중단 조건

다음 중 하나라도 해당하면 YAML을 만들지 않고 `REPORT_NEEDS_INPUT_V1`을 반환한다.

- 학생 보고서 후보가 없거나 둘 이상임
- 본문에서 학생명을 확인할 수 없음
- 요청 학생명과 본문 학생명이 다름
- 학생 신원이나 핵심 활동 결과가 서로 충돌하여 불확실한 부분만 제외하고 진행할 수 없음
- 문서 본문을 추출할 수 없음
- 활동 과정과 결과에 해당하는 실질적인 내용이 없음
- 필수 내용이 이미지에만 있어 텍스트로 확인할 수 없음

```yaml
contract: REPORT_NEEDS_INPUT_V1
report_path: ""
active_report_directory: "보고서/"
available_docx_filenames: []
questions:
  - field: ""
    question: ""
```

## 완료 보고 계약: `REPORT_INGESTED_V1`

```yaml
contract: REPORT_INGESTED_V1
report_path: "보고서/<파일명>.docx"
student_name: ""
yaml_path: "학생정보/<학생명>.yaml"
saved: true
activity_count: 1
uncertain_fields: []
warnings: []
excluded_uncertain_facts: []
```

모든 계약 응답은 `yaml` 코드 블록 하나로 끝까지 출력한다. 실제 파일명은 `*` 같은 Markdown 문자로 바꾸지 말고 파일 시스템에서 확인한 문자열을 그대로 복사한다. 완료 후에는 YAML 경로, 활동 수, 비워 둔 불확실 필드와 비차단 경고만 보고한다. 보고서 전문이나 학생 개인정보를 채팅에 반복 출력하지 않는다.
